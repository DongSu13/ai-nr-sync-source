# AI-Assisted NR Synchronization

[中文](README.md) | [English](README.en.md)

This repository provides NR synchronization simulation code: PSS/CFO front-end synchronization, multi-transmitter (cell) PBCH reception, successive interference cancellation (SIC), and AI-assisted candidate ranking. Inputs are generated synthetically by the code; no external dataset download is required.

The code studies two separate questions:

1. Under the same waveform and PSS correlation implementation, can a single AI CFO proposal improve correct PSS-peak detection and CFO RMSE over a single classical autocorrelation CFO proposal?
2. Under the same PBCH decoding budget, can AI candidate ranking help the SIC chain recover more true transmitters?

There is no FPGA deployment, real RF capture, or live network experiment here. All data are generated by the code. The approximate multipath channel is intended for comparative simulation, not full 3GPP conformance testing.

## Method

```text
received samples -> CFO estimation/compensation -> PSS peak and N_ID2
                 -> SSS and PCI -> PBCH DM-RS channel estimate
                 -> Polar decode + CRC -> confirmed-user reconstruction
                 -> SIC -> residual search
```

The front-end AI component supplies the CFO proposal; the final PSS search still uses the same correlator. The multi-user AI component ranks candidates, while PBCH CRC and SIC remain part of the physical receive chain. The repository also includes classical grid search, classical autocorrelation, CNN/CNN-LSTM models, expanded model families, and statistical audit utilities.

## Layout

| Path | Contents |
| --- | --- |
| `src/python/` | Synthetic scenes, PSS/CFO models, training, candidate ranking, statistical audits, and runners |
| `src/matlab/` | SS/PBCH reception, multi-user SIC, MATLAB link scripts, and 5G Toolbox probes |
| `configs/` | Small baseline and candidate-generation configurations |
| `tests/` | Generator, model-interface, audit, MATLAB-launcher, and core algorithm tests |

The default output root is `outputs/`. Generated data, model weights, waveforms, logs, and reports are ignored by Git.

## Setup

The dependency ranges target Python 3.12. In the commands below, `python` must refer to your selected Python 3.12 interpreter; check `python --version` before creating the environment:

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
python -m pytest tests -q
```

CUDA training tests are skipped when CUDA is unavailable. MATLAB link experiments require MATLAB R2022a or a compatible release with 5G Toolbox. The MATLAB executable is resolved from `MATLAB_BIN` or `PATH`:

Add MATLAB to `PATH`, or set `MATLAB_BIN` to the local `matlab` executable, then run:

```powershell
python src/python/matlab_launcher.py v4 development
```

`development` generates the training and development data first and runs a substantial simulation campaign. After it completes, run `v4 final` for model selection and independent evaluation. Use `v4 all` to run both stages sequentially.

These training smoke examples require a CUDA GPU and an output directory that does not already exist:

```powershell
python src/python/run_paper_aligned.py --output outputs/paper_aligned_smoke --smoke
python src/python/run_paper_repro.py --output outputs/paper_repro_smoke --train 16 --val 8 --test 8 --epochs 1
```

These commands generate synthetic data and models. The standalone CFO experiment trains from random initialization by default; `--initial-weights` accepts a compatible checkpoint you generated. Expanded-model comparisons require `--reference-weight` in `develop` mode; the four-model runner above produces `weights/cross_cnn.pt` for that purpose.
